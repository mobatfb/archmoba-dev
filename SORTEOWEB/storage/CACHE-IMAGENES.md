# Cache de fotografias (v1.2.12)
- PHP GD con lectura JPG, PNG y WebP y soporte de escritura WebP permite generar miniaturas de 480 px y versiones medianas de 1000 px (lado mayor, sin ampliar). Se conservan originales intactos. Si no se puede redimensionar de forma segura, se utiliza el original; no se inventa una miniatura.
- El directorio `storage/photo-cache/` se crea automaticamente si no existe. PHP debe poder escribir en el. Tanto `storage/` como el subdirectorio estan protegidos por .htaccess; verificar que el servidor no permita su descarga directa. Las solicitudes publicas comprueban que el sorteo esta activo y las administrativas mantienen la autorizacion. No almacenar aqui claves ni documentos.
- La primera solicitud de cada foto/tamano crea una copia optimizada en disco. Las siguientes solicitudes consultan solamente los metadatos y reutilizan el archivo. El navegador conserva las URL versionadas durante 24 horas; las URL antiguas y las privadas revalidan con ETag. Las imagenes de dinero usan un unico SVG estatico.
- La galeria de detalles carga versiones medianas solo al abrirla. El visor carga el original. Los carruseles preparan la siguiente foto y no cambian hasta que se haya cargado.
- No se requiere migracion SQL ni volver a subir fotos. Para recuperar espacio se pueden borrar los archivos generados de `storage/photo-cache/` (excepto .htaccess), preferiblemente en mantenimiento; se regeneran al solicitarlos. Nunca borres `storage/uploads/` ni los originales de la base de datos.
- Verificar GD/WebP, permisos de escritura, Cache-Control y ETag en el hosting. Las miniaturas no se generan si faltan las extensiones o la memoria disponible no permite decodificar de forma segura.
